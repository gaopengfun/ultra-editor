修复链接地址里的括号与空格在 Markdown 往返中丢失

进出一次 Markdown 源码模式,下面几种链接会被改坏,而且都是静默的:

- `https://en.wikipedia.org/wiki/Ruby_(programming_language)` —— 地址被截到
  `..._(programming_language`,多出来的 `)` 掉进正文当普通文字。维基百科、MSDN
  的地址大量带括号,这是最容易撞上的一种。
- `https://x.com/a b`(带空格)、`https://x.com/a(b`(括号不配对) —— 整个链接读不
  回来,变成一行字面量 `[文字](地址)`。

两侧各有一个原因。

解析侧:裸地址用 `[^\s)]*` 匹配,遇到第一个 `)` 就停。CommonMark 明确允许裸地址
里出现**配对**的括号,所以这是解析器不够格,别人用 GitHub 写好的 Markdown 粘进来
同样会被截断。改成支持两层嵌套的配对括号——正则数不了任意深度,但真实地址不会更深,
再深的仍按第一个不配对的 `)` 结束,与原行为一致。两个分支的首字符互斥,引擎没有可
回溯的分歧点,4 万字符的病态输入实测不到 1ms。

序列化侧:`[文字](地址)` 一直是直接把 href 拼进去,从不使用 `<...>`。而带空格、
括号不配对的地址只有 `<...>` 这一种写法能读回来——解析器早就支持这个分支,只是没
人往里写。现在按"裸写能否原样读回"来决定包不包,能裸写的照旧裸写,输出不变噪。

20 组文档结构做 HTML → Markdown → HTML 往返比对,修复前 3 组被改坏,修复后 0 组。
