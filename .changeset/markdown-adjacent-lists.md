修复 Markdown 解析的两处块级边界问题。

**相邻列表之间静默丢内容**

`- a` 紧跟 `1. b`（中间没有空行）时，只有第一段列表会被渲染，之后的所有列表项**直接消失**。`renderList` 一撞到 level 或标记类型不同的项就停下并返回停在哪儿，但调用方丢掉了这个返回值，剩下的项无人渲染。`1. one` 接 `- two`、以及缩进更深的项后面跟着更浅的项，都走同一条路径。

手写和模型生成的 Markdown 正是这样把两段列表连着写的，而 `MarkdownPaste` 吃的就是任意剪贴板内容 —— 于是粘贴一段普通文档就会悄悄少掉几行。现在每一段连续的同类列表各渲染成一个列表，一项不落。

此前的测试用 `'- a\n\n1. b'`（带空行）验证「切换列表类型」，走的是另一条本来就正常的路径，所以一直没暴露。

**引用块惰性续行漏判有序列表与围栏代码块**

`> 引用` 后面紧跟 `1. 列表` 或 ```` ``` ```` 时，它们会被吸进引用块里 —— 而同样位置的 `- 列表` 和 `# 标题` 会正确地结束引用。判断条件里检查了 `BULLET` 和 `HEADING`，唯独漏了另外两个。现在按 CommonMark 处理：有序列表只有**以 `1.` 开头**才能打断段落，`2.` 之类不算（否则句子折行到 `2. ` 会被劈成两半）。

分割线仍不结束引用：`---` 直接跟在正文行下面是 setext 标题的下划线，而本解析器不支持 setext，在那里断开只是把一种错误换成另一种。
