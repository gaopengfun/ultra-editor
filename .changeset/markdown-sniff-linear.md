修复粘贴大段纯文本时 Markdown 嗅探可能卡住主线程。

`looksLikeMarkdown` 判断加粗和删除线用的是 `\*\*(?=\S)[\s\S]*?\S\*\*` 这类惰性正则。每遇到一个后面紧跟非空格、却在全文中找不到配对的 `**`，惰性量词就要扫到字符串末尾再回溯一次——开销随输入平方增长。实测 453 KB 纯文本里 8000 处未配对 `**` 要 0.7 s，906 KB / 16000 处要 **2.7 s**，全程卡死主线程。粘贴 Python 代码（`**kwargs`、`2**n`）或中文里把 `~~` 当波浪号用都对得上这个形状，只要文本里没有任何块级 Markdown 信号（那会提前返回）就会命中。

改成一次线性扫描。之所以扫一遍就够：靠后的开标记能够到的闭标记，一定是靠前那个能够到的子集——第一个开标记找不到配对，后面的也不会有。判定结果与原正则完全一致，已用 `{*, ~, 空格, a, 换行}` 五个字符组合出的全部 97656 个长度 ≤7 的字符串逐一比对过，零差异。同一输入现在约 1 ms。

同时确认块级信号那七条正则都是线性的（单行 8000 个 `-` 或 8000 个表格分隔单元格都在 0.4 ms 内），不需要处理。
