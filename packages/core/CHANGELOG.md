# @ultra-editor/core

## 1.2.0

### Minor Changes

- 8488fc4: 代码块语言选择器补上 TOML 和 HTML

  选择器的列表来自 `lowlight.listLanguages()`,而它返回的是注册的语法**名**。
  highlight.js 把 TOML 归在 `ini` 下、HTML 归在 `xml` 下,两者都只是别名,于是这两个
  语言从来没能出现在下拉里 —— 尽管 `highlight('toml', …)` 本身完全正常。净效果是
  写 TOML 的人只能把自己的块标成「INI」,写 HTML 的人只能标成「XML」。

  现在按别名单独列出,以「该语法确实注册了」为前提:宿主自带语言集时,不会被塞进一个
  点了也画不出高亮的选项。

  高亮结果与 `ini` / `xml` 完全一致 —— 同一份语法,区别只在 `language` 属性和显示
  标签,以及 Markdown 围栏的信息串是 `toml` 还是 `ini`。这正是作者的本意,应当保留。

- 8488fc4: 只读页的代码块右上角显示语言角标

  编辑态的代码块一直有工具条,左上角的选择器明写着这块是什么语言;只读页把同一份 HTML
  包进 `ue-content` 之后,这个信息就只剩 `<code>` 上那个 `language-` 类,对读者是不可见的
  —— 一段 Rust 和一段 Go 在页面上长得一模一样。

  角标取自 `<pre>` 上的 `data-language`,也就是 `renderHTML` 本来就会写出的那个属性,
  不需要额外的标记或运行时。大写展示。

  没有标语言的块不显示角标。`attr()` 读不到属性时返回的是空串而不是 `none`,伪元素照样
  生成,单靠 padding 和背景就能画出一颗空药丸;而 `content.css` 是编辑态与只读态共用的
  同一份样式,不收口的话每个正在编辑的代码块右上角都会多出这么一颗。

- fcc37f1: 代码块语言选择开箱可用，语言目录改为按需加载。

  - `@ultra-editor/vue` 此前从不注册任何 lowlight 语言：代码块语言下拉只有「纯文本」，且**完全没有语法高亮**。现在不传 `lowlight` 时会在挂载后把 lowlight 的 common 语言集作为独立异步 chunk 拉进来（gzip ~43 KB，不进主包），并重绘已经画在屏幕上的代码块。传 `lowlight` 则完全以宿主为准，不发起任何加载。
  - 新增 `loadCommonLanguages(lowlight)` 与 `refreshCodeHighlighting(editor)` 两个导出，自己组装扩展的宿主可以复用同一套按需加载逻辑。
  - 语言列表改为打开菜单时才构建：此前每个代码块在 node view 创建时就生成 38 个按钮，长文档全额付费；且构造之后注册的语言永远进不了列表。

- 4766855: 取色器自绘自定义颜色，代码块语言写入 `pre[data-language]`，修掉 Markdown 源码往返多出来的空行。

  **取色器**：自定义颜色原先是一个 `<input type="color">`，色块由浏览器绘制，点开弹出的是浏览器自己的取色面板（直角、系统数字框、系统吸管），和编辑器的设计语言完全两套，且无法改写样式。现在色板 24 色不变，操作条上多一个「自定义」，点开才展开饱和度区、色相条与 hex 输入框，面板默认尺寸不变。拖拽只改草稿，「应用」才写回文档 —— 一次拖拽几十个事件，逐个写会把 undo 栈埋掉。表格右键菜单的底色面板用的是同一个组件，一并受益。core 新增 `hexToHsv` / `hsvToHex` / `normalizeHex` 三个导出。

  **代码块语言**：上游只把语言记在 `<code>` 的 `class` 上，而 `class` 是 HTML 清洗的第一个牺牲品，保存一趟回来语言就没了。现在同时写到 `<pre data-language="…">`，解析时优先读它，读不到再退回 `language-` class —— 旧文档、Markdown 围栏产出的 HTML、外部粘贴的内容都照旧识别。

  **源码模式空行**：四处独立的原因。① 退出源码模式时的空操作守卫比较的是两种 HTML 方言（`markdownToHTML` 写 `<li>文本</li>`，ProseMirror 写 `<li><p>文本</p></li>`），含列表或表格的文档永不相等，于是没改动也照样回写一次，凭空占掉一格 undo；改为在 Markdown 上比较。② 连续两个硬换行时，第二个写出的是一行只有 `  ` 标记的行，而空行正是 Markdown 结束段落的方式，读回来一个段落被劈成两个；无处可断的硬换行现在直接丢弃。③ 列表项里的第二个块，读回来时那个空行被当成列表结束，续段变成顶层段落并把列表劈成两截，`- 一\n\n  续段\n- 二` 往返一次就成了 `- 一\n\n续段\n\n- 二`；空行后跟缩进行现在正确识别为松散列表项的内部分隔。④ 标题和表格单元格在 Markdown 里都只有一行可用，硬换行原样写出会让标题后半截掉成段落、单元格里留下一段空隙，现在连同 `  ` 标记一起折成一个空格。

- bb15507: 新增 Markdown 编辑能力：双向转换、粘贴自动识别、Vue 源码模式。

  - `docToMarkdown(doc)` 与 `markdownToHTML(md)` —— 针对本编辑器 schema 手写的双向转换，不引第三方 Markdown 依赖（`prosemirror-markdown` 认不得表格、图注和分栏）。覆盖标题、段落、加粗 / 斜体 / 删除线 / 行内代码 / 链接、有序与无序列表（含嵌套）、引用、围栏代码块（带语言）、分割线、图片、GFM 表格与硬换行；Markdown 表达不了的（下划线、文字颜色、分栏）降级为纯文本而不是丢失。整套转换约 3.3 KB（gzip）。
  - `MarkdownPaste` 扩展：粘贴纯文本时，只有在内容**明确**是 Markdown（`looksLikeMarkdown`：一个块级语法即可，行内语法需两种以上）才转成富文本。剪贴板带 `text/html` 时让位给 ProseMirror 自己的解析器；代码块内粘贴保持原样。可通过 `markdownPaste` getter 运行时开关，或 `features.markdown: false` 整个摘掉。
  - Vue 组件新增 Markdown 源码模式：工具栏切换后编辑区换成 textarea，退出时套用回文档。源码模式下 textarea 是唯一事实来源（不反向重排作者正在敲的字），编辑内容按 `debounce`（默认 300ms）同步进文档，`v-model` 全程可信；未退出就卸载也会先落盘。
  - Vue 组件新增 `getMarkdown()` / `setMarkdown()`，以及 `markdown` prop（默认开）。
  - 解析器把源码里的裸 HTML 转义而非放行，`javascript:` 链接与非图片 `data:` URL 一律拒绝 —— 从剪贴板来的 Markdown 是不可信输入。
  - 新增文案 `toolbar.markdown` / `markdown.exit` / `markdown.placeholder`（`zhCN` 与 `en`）。

### Patch Changes

- 3d9060e: 修复 AI 面板重开与重试时旧生成未被中止的问题，并补齐全量单元测试。

  **修复**

  - 在一次生成尚未结束时再次发起（`start` / `submit`），旧的 `AIRun` 会被直接丢弃而不中止：它的流继续拉取、继续计费，`onChunk` 也继续往共享面板状态里写，`stop()` 之后只能中止最新的那一次。`useAi` 内部改为统一走 `abandon()`——换掉一次生成之前必定先 `abort()`。`transform` 模式下编辑器不上锁、气泡菜单仍然可用，从 UI 上就能触发。
  - 「重试」会让面板停在「已完成」，而新的生成还在流式写入：`retry()` 先 `abort()` 再同步 `execute()`，但中止要到下一个微任务才落地，于是那次已经作废的生成的 `onAbort` 反而把 `phase` 又改回了 `done`——用户会在还在生成时看到接受 / 丢弃按钮。作废的生成现在带世代号，落后的回调不再写入当前状态。

  **内部**

  - `createUltraKit` 的 `upload.fetchImage` 没有任何扩展会读取：重新编码已有图片属于外壳的职责，旋转与裁切直接调用 `upload.fetchImage`。`UltraEditor` 不再把它透传进 kit。

- 00d1311: 未指定语言的代码块不再猜语言，「PlainText」现在真的是纯文本

  上游的 lowlight 插件在 `language` 为空时会退回 `highlightAuto()`,而语言选择器把这种块标成「PlainText」。两件事对不上:标签承诺不高亮,渲染出来却是猜出来的高亮。

  而且猜得不准。拿 10 段典型片段实测,**5 段判错**:JavaScript 箭头函数判成 `ini`(于是结尾的 `;` 被涂成注释色)、Go 判成 `csharp`、Java 判成 `typescript`、HTML 判成 `php-template`、Bash 判不出来。人们贴进代码块的片段大多就是这个长度,猜错是常态而非例外。

  现在把注入的 lowlight 实例包一层、只关掉 `highlightAuto`,让标签说到做到:未指定语言 = 不高亮。显式选了语言的块走 `highlight()`,行为完全不变。包装用原型委托而非拷贝,`loadCommonLanguages` 之后注册进来的语法照样可见。

  `data-language` 与 Markdown 围栏的信息串都不受影响——文档里存的仍然是"没有语言",不会凭空多出 `plaintext`。

- 70ba1cf: 代码块语言选择器里的默认项，中文语境下由「纯文本」改为 `PlainText`。

  那个下拉列出的是 highlight.js 的语言名（JavaScript、CSS、Rust……），到哪个语言环境都是专有名词、不翻译，「纯文本」是其中唯一一个读起来像中文的条目。英文语境保持 `Plain text` 不变 —— 那里本来就是英文，改成驼峰只会更别扭。

- 1dc75ce: 修复单元格底色的自动文字颜色挑到可读性更差的那个

  `contrastText` 原先用 YIQ 亮度公式(0.299/0.587/0.114)配 0.6 阈值来二选一,而这个公式吃的是**伽马编码后**的通道值,会高估饱和中间色的亮度。结果在中间调上,它挑的恰恰是两个候选里更难读的那个:内置 24 个色板中有 **5 个**落到这一区,且 5 个**全部**挑反。`#51a5dc` 配白字只有 2.70:1,配深字有 5.43:1——挑的是白字。

  改为按 WCAG 相对亮度算出两个候选各自的对比度,取高的那个。不再有阈值,交叉点自然落在两者相等处(灰阶上在 `#828282` 与 `#838383` 之间)。24 个色板里低于 AA 4.5:1 的从 5 个降到 3 个,最差对比度从 2.70:1 提到 3.99:1;剩下 3 个是深/白双色方案对那几个饱和中间色的固有上限,但每一个拿到的都已是两者中更好的一个。

  原测试 `treats a luminance of exactly 0.6 as dark...` 把 0.6 这个阈值本身写进了断言——`#999999` 配白字 2.85:1、配深字 5.16:1,断言要的却是白字。它锁的是缺陷,已换成按对比度交叉点断言。

- 9ad483a: 修复链接地址里的括号与空格在 Markdown 往返中丢失

  进出一次 Markdown 源码模式,下面几种链接会被改坏,而且都是静默的:

  - `https://en.wikipedia.org/wiki/Ruby_(programming_language)` —— 地址被截到
    `..._(programming_language`,多出来的 `)` 掉进正文当普通文字。维基百科、MSDN
    的地址大量带括号,这是最容易撞上的一种。
  - `https://x.com/a b`(带空格)、`https://x.com/a(b`(括号不配对) —— 整个链接读不
    回来,变成一行字面量 `[文字](地址)`。

  两侧各有一个原因。

  解析侧:裸地址用 `[^\s)]*` 匹配,遇到第一个 `)` 就停。CommonMark 明确允许裸地址
  里出现**配对**的括号,所以这是解析器不够格,别人用 GitHub 写好的 Markdown 粘进来
  同样会被截断。改成支持两层嵌套的配对括号——正则数不了任意深度,但真实地址不会更深,
  再深的仍按第一个不配对的 `)` 结束,与原行为一致。两个分支的首字符互斥,引擎没有可
  回溯的分歧点,4 万字符的病态输入实测不到 1ms。

  序列化侧:`[文字](地址)` 一直是直接把 href 拼进去,从不使用 `<...>`。而带空格、
  括号不配对的地址只有 `<...>` 这一种写法能读回来——解析器早就支持这个分支,只是没
  人往里写。现在按"裸写能否原样读回"来决定包不包,能裸写的照旧裸写,输出不变噪。

  20 组文档结构做 HTML → Markdown → HTML 往返比对,修复前 3 组被改坏,修复后 0 组。

- bf334a4: 修复 Markdown 解析的两处块级边界问题。

  **相邻列表之间静默丢内容**

  `- a` 紧跟 `1. b`（中间没有空行）时，只有第一段列表会被渲染，之后的所有列表项**直接消失**。`renderList` 一撞到 level 或标记类型不同的项就停下并返回停在哪儿，但调用方丢掉了这个返回值，剩下的项无人渲染。`1. one` 接 `- two`、以及缩进更深的项后面跟着更浅的项，都走同一条路径。

  手写和模型生成的 Markdown 正是这样把两段列表连着写的，而 `MarkdownPaste` 吃的就是任意剪贴板内容 —— 于是粘贴一段普通文档就会悄悄少掉几行。现在每一段连续的同类列表各渲染成一个列表，一项不落。

  此前的测试用 `'- a\n\n1. b'`（带空行）验证「切换列表类型」，走的是另一条本来就正常的路径，所以一直没暴露。

  **引用块惰性续行漏判有序列表与围栏代码块**

  `> 引用` 后面紧跟 `1. 列表` 或 ` ``` ` 时，它们会被吸进引用块里 —— 而同样位置的 `- 列表` 和 `# 标题` 会正确地结束引用。判断条件里检查了 `BULLET` 和 `HEADING`，唯独漏了另外两个。现在按 CommonMark 处理：有序列表只有**以 `1.` 开头**才能打断段落，`2.` 之类不算（否则句子折行到 `2. ` 会被劈成两半）。

  分割线仍不结束引用：`---` 直接跟在正文行下面是 setext 标题的下划线，而本解析器不支持 setext，在那里断开只是把一种错误换成另一种。

- 23b32c6: 修复粘贴普通正文时数字被吞:按 CommonMark 限制有序列表打断段落。

  正文里只要有一行以「数字 + 句点」开头（年份、价格、编号、条款序号），那个数字就会被当成列表序号消费掉，**从正文里彻底消失**，同时整段被重排成列表：

  ```
  我家窗户是
  14. 门是 6
  ```

  此前得到 `<p>我家窗户是</p><ol><li>门是 6</li></ol>` —— `14` 没了。而 `looksLikeMarkdown` 会放行这段文本，所以粘贴板路径直接可达：不需要用户懂 Markdown，从 PDF、邮件、聊天记录里复制一段硬换行的中文正文就会中招。这与 `MarkdownPaste` 自身「把别人的普通段落重排比原样落地更糟」的设计前提相悖。

  现按 CommonMark 处理：**只有项目符号、或以 `1.` 开头的有序列表才能打断进行中的段落**，其余数字标记是句子的一部分。

  修复覆盖两条独立代码路径共四个位置 —— 顶层、引用块内、列表项内、更深层嵌套。前两者走 `blocksToHTML` 的列表分支，后两者走列表项收集循环，规则不同：后者要求标记「缩进比上一项更深」才算开子列表，否则 `- 步骤` / `1. 先做` / `2. 再做` 里的 `2.` 会被误判成正文。

  不受影响：以任意数字起块的列表仍是列表（复制长列表的第 5-8 项），`正文` 后接 `- ` 或 `1. ` 仍正常打断，同级有序项的编号连续性不变，序列化 → 解析的 round-trip 全程未受影响（序列化器块间固定空行，踩不到这条路径）。

- a7331df: 修复 Markdown 序列化的两处转义缺口:切换源码模式会改坏文档。

  进出 Markdown 源码模式（工具栏按钮）走的是一次完整的 doc → Markdown → doc 往返，`getMarkdown()` / `setMarkdown()` 同理。序列化器的转义字符集与解析器的可转义字符集没有对齐，于是这趟往返会改动文档：

  **`~` 不在转义集里。** 后果分两级：

  - `~~开心~~啦` 存盘再打开变成 `<s>开心</s>啦` —— 文字被加上了用户没加的删除线。
  - 段落里的 `~~~` 被读成**围栏代码块开头**，由于没有闭合，**它之后的整篇文档都被吞进 `<pre><code>`**。

  现在 `~` 与其他语法字符一样转义；解析器的可转义集本就含 `~`，`\~` 能正确还原。真删除线不受影响（标记包裹发生在文本转义之后），删除线文字里带波浪线也能正常往返。

  **数字开头的段落写出了无效转义。** `1. 正文` 此前被写成 `\1. 正文`，但 `\1` 不是合法的 Markdown 转义 —— 只有标点可转义 —— 所以解析器把反斜杠原样还给正文，作者会看到一个自己没打过的 `\`。反斜杠现在放在标点前（`1\.`）：数字后没有紧跟 `.` 就不会被读成列表，而 `\.` 能正确还原。`1)` 这类同理。

  此前的测试只断言 `\1.` 能阻止它被读回成列表，没有验证往返，所以这个多余的反斜杠一直没暴露。

- 4c38331: 修复粘贴大段纯文本时 Markdown 嗅探可能卡住主线程。

  `looksLikeMarkdown` 判断加粗和删除线用的是 `\*\*(?=\S)[\s\S]*?\S\*\*` 这类惰性正则。每遇到一个后面紧跟非空格、却在全文中找不到配对的 `**`，惰性量词就要扫到字符串末尾再回溯一次——开销随输入平方增长。实测 453 KB 纯文本里 8000 处未配对 `**` 要 0.7 s，906 KB / 16000 处要 **2.7 s**，全程卡死主线程。粘贴 Python 代码（`**kwargs`、`2**n`）或中文里把 `~~` 当波浪号用都对得上这个形状，只要文本里没有任何块级 Markdown 信号（那会提前返回）就会命中。

  改成一次线性扫描。之所以扫一遍就够：靠后的开标记能够到的闭标记，一定是靠前那个能够到的子集——第一个开标记找不到配对，后面的也不会有。判定结果与原正则完全一致，已用 `{*, ~, 空格, a, 换行}` 五个字符组合出的全部 97656 个长度 ≤7 的字符串逐一比对过，零差异。同一输入现在约 1 ms。

  同时确认块级信号那七条正则都是线性的（单行 8000 个 `-` 或 8000 个表格分隔单元格都在 0.4 ms 内），不需要处理。

- 73e5bef: 修复 `readSSE` 提前退出时不关闭响应体。

  此前提前退出只 `releaseLock` 不 `cancel`，响应体不会关闭。两个内置 provider 都在 `[DONE]` / `message_stop` 处 `return`，所以每一次 AI 请求都走这条路径。

- f76519e: 修复文字颜色面板里的清除按钮写着「清除底色」

  工具栏的颜色面板直接借用了表格菜单的文案键 `table.clearColor`,于是「文字颜色」
  面板里那颗按钮写的是「清除底色」——英文更直白,`Text color` 面板里写着
  `Clear background`。两个面板改的根本不是同一件事:一个改文字颜色,一个改单元格
  背景色。

  新增 `toolbar.clearColor`(清除颜色 / Clear color)给文字颜色面板用,表格菜单继续
  用 `table.clearColor`。

- 0a2eb04: 优化输入时的每次事务开销：字数统计不再全文跑正则，气泡菜单不再重复测量。

  `@tiptap/vue-3` 把编辑器 state 包成响应式 ref，**每个事务都会重新发布**——包括纯光标移动。于是状态栏的字数统计每次都重跑一遍：`getText()` 拿到全文后，`replace(/\s/g)` 复制一份文档、`match(/[一-龥]/g)` 生成一个「每个汉字一个字符串」的数组、再 `replace` + `match` 一次。157 KB 文档上实测单次 3.0 ms，方向键移动光标也照付。现在按文档对象缓存（光标移动直接复用上次结果），统计本身也改成按 char code 的单趟扫描，实测 0.43 ms，快 7 倍。空白字符集与单词字符集已对 BMP 全部 65536 个码位逐一比对过，与原正则完全等价——包括扩展区汉字仍不计入这一既有行为。

  气泡菜单同时监听了 `transaction` 和 `selectionUpdate`。Tiptap 对同一次 dispatch 先发前者、紧接着发后者，所以选区一动 `update()` 就跑两遍，每遍两次 `coordsAtPos`——而 `coordsAtPos` 会强制同步布局。只留 `transaction` 即可，它是前者的严格超集。

  Markdown 序列化里代码块的围栏计算把 `node.textContent` 当循环条件用，而它是每次访问都从子节点重建字符串的 getter，一个代码块要重建 2~3 次。改为只读一次。

## 1.0.0

AI Native 编辑器 SDK 首个正式版本。

- **AI Native**：斜杠命令面板、选区 AI 气泡菜单、文档内流式生成（可中断 / 重试 / 丢弃）、Tab 接受的幽灵文本补全。通过 `AIProvider` 接口注入，不绑定任何厂商；附赠 OpenAI 兼容与 Anthropic 适配器。

- 编辑器能力：图片（旋转 / 裁切 / 8 锚点缩放 / 对齐 / 图注 / 粘贴与拖拽上传）、1-5 栏卡片、可拖拽行高列宽与单元格底色的表格、代码高亮、字数统计、中英文 i18n、只读模式、SSR guard。
